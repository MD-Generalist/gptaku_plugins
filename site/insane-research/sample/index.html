3. Windows 구현 가이드 — 확정분

토스트 발화

  • PS 5.1 WinRT 원샷: 외부 의존성 0으로 [Windows.UI.Notifications.ToastNotificationManager, …, ContentType = WindowsRuntime] 타입 로드 → 템플릿 XML → CreateToastNotifier(<AppId>).Show(). 단 원샷 스크립트는 프로세스가 종료돼 activation 이벤트를 못 받으므로 클릭 무반응이 기본.
  • BurntToast v1.0: 2025-07 v1.0 도달, PS Gallery 2,500만+ 다운로드, Windows 10/11·PS 5.1·7.3+ 호환으로 활발히 유지보수. v1.0의 ActivatedAction script block으로 클릭 시 포커스 스크립트 실행 가능 — 클릭 동작이 필요하면 이 경로가 가장 실용적.
  • WSL: powershell.exe interop으로 WinRT 스크립트 직접 호출, 또는 wsl-notify-send.exe를 notify-send 셸 함수로 감싸 Stop 훅에서 호출(클릭 동작 미지원).

부모 터미널 식별

  • 1차 env 판별 — 검사 순서가 핵심(안쪽 변수 우선): TERM_PROGRAM=vscode(VS Code 계열) → WT_SESSION+WT_PROFILE_ID(Windows Terminal) → ConEmuPID(ConEmu/cmder) → mintty(Git Bash 자체 창). 상속 오탐 주의: Windows Terminal에서 VS Code를 열면 VS Code 통합터미널에도 WT_SESSION이 남는다 — vscode 검사를 먼저 해야 한다.
  • 2차 폴백 — 부모 프로세스 추적: PowerShell로 프로세스 트리를 거슬러 known 터미널 exe(WindowsTerminal/wezterm-gui/alacritty/Code/ConEmu64/Cursor/mintty/Hyper/Tabby…)를 찾는다. Windows Terminal은 직계 부모가 아닐 수 있어 전체 계보 검사가 필요하다.
  • WSL에서의 식별: WSL2는 VM이라 /proc으로 Windows 프로세스가 안 보이고 부모 추적도 wslhost에서 끊긴다. 실용 경로는 환경변수 월경 — Windows Terminal은 WSLENV로 WT_SESSION·WT_PROFILE_ID를 WSL 안까지 전달한다.
  • 클릭 포커스: 표준 패턴은 터미널 프로세스 MainWindowHandle에 SetForegroundWindow(+ShowWindowAsync) P/Invoke, 간단 대안은 (WScript.Shell).AppActivate(PID). 제약: 포그라운드 잠금 정책상 사용자가 다른 창 작업 중이면 강제 전환이 거부될 수 있다(작업표시줄 깜빡임 폴백).
  • Git Bash 훅 판별 함수(bash 몇 줄): env 1차 → powershell.exe 부모 추적 폴백 구조가 실증돼 있다.
